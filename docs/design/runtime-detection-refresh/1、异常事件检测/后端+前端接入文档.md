# 异常检测设置设计说明

日期：2026-09-05

## 背景

本设计面向一个新的“异常检测设置”页面。页面上半部分维护通用异常检测配置，下半部分维护不同 AgentType 的专属异常检测配置。

用户期望的规则组合关系是：

```text
最终异常检测规则
  =
通用异常检测规则
  +
AgentType 专属异常检测规则
  +
AgentType 黑名单规则
```

如果某个 AgentType 关闭“继承通用异常检测规则”，则变为：

```text
最终异常检测规则
  =
AgentType 专属异常检测规则
  +
AgentType 黑名单规则
```

风险判定也采用继承关系：

```text
使用通用风险判定规则 = true
  -> 使用全局风险分值区间和等级到决策的映射

使用通用风险判定规则 = false
  -> 使用该 AgentType 自定义风险判定规则
```

## 当前代码观察

当前项目里已经有一部分能力可以复用，但还没有完整的“异常检测设置”模型。

| 模块 | 当前情况 | 设计影响 |
| --- | --- | --- |
| `internal/detection/rules.go` | `DefaultRules()` 返回硬编码的通用 runtime 检测规则 | 可以作为默认通用规则来源，但需要增加 DB 配置层 |
| `internal/detection/engine.go` | 检测引擎注释强调 rule 是 agent-agnostic，不特殊区分 Claude Code / Codex / OpenClaw | 不建议直接改 Go 内置规则逻辑，应在其外层增加 AgentType overlay |
| `internal/gateway/detection_rules_api.go` | 目前只有 `GET`，返回 active engine 的规则列表 | 需要新增可编辑的异常检测设置 API |
| `internal/audit/runtime_detections.go` | runtime detection 已包含 `agent_type_id`、`agent_type_name`、`rule_id`、`rule_version` 等字段 | 可以支撑按 AgentType 查看和回放后的归因 |
| `internal/detection/policy.go` | `Decide()` 和 `RiskScore()` 目前硬编码 severity/category/confidence 到决策 | 需要改成读取风险判定策略 |
| `internal/audit/risk_explain.go` | 现有 risk explain 主要用于静态资源治理风险解释 | 不建议直接复用为 runtime 异常检测风险规则，只适合作为参考 |
| `internal/gateway/agent_governance_api.go` | 已有 AgentType、资源规则、扫描方案、静态风险解释等治理 API | 异常检测设置可以放在同一治理体系下，但建议接口前缀独立 |

结论：新设计应该新增一层 **Runtime Detection Settings**，不要把 AgentType 专属异常检测直接塞进当前 `DefaultRules()`，也不要把静态资源风险解释表直接当作运行时异常风险判定表。

## 页面信息架构

### 上半部分：通用异常检测配置

包含两块：

1. 通用异常检测规则
   - 支持新增、编辑、删除、启停。
   - 内置规则可以启停和修改部分展示/判定参数。
   - 内置规则不建议物理删除，“删除”可以实现为软删除或隐藏。

2. 通用风险判定规则
   - 当前只展示，不编辑。
   - 展示默认等级、分值区间和动作映射。
   - 建议默认展示：

| 风险等级 | 分值区间 | 前端展示动作 | 后端决策值 |
| --- | --- | --- | --- |
| LOW | `0.00 - 0.39` | ALLOW | `ALLOW` |
| MEDIUM | `0.40 - 0.69` | ALERT | `ALERT` |
| HIGH | `0.70 - 0.89` | ASK | `CONFIRM` |
| CRITICAL | `0.90 - 1.00` | BLOCK | `BLOCK` |

说明：当前后端已有 `CONFIRM`，没有 `ASK`。前端可以展示为“ASK / 需确认”，后端仍保存 `CONFIRM`，避免破坏已有 `runtime_decisions` 链路。

### 下半部分：AgentType 专属配置列表

列表建议字段：

| 字段 | 说明 |
| --- | --- |
| AgentType | Agent 类型名称 |
| 是否启用通用检测规则 | 是否继承通用异常检测规则 |
| 专属规则数 | 当前 AgentType 自己配置的异常检测规则数量 |
| 黑名单数 | 当前 AgentType 黑名单条数 |
| 风险判定方式 | 通用 / 自定义 |
| 状态 | 启用 / 停用 |
| 操作 | 详情 |

点击详情后弹窗中包含：

```text
AgentType 专属配置
  1. 专属异常检测规则
  2. 黑名单
  3. 风险判定方式
```

弹窗顶部建议展示基础设置：

- 是否启用该 AgentType 异常检测。
- 是否继承通用异常检测规则。
- 是否使用通用风险判定规则。

## 后端设计

### 新增领域

建议新增一个独立领域：`runtime_detection_settings`。

它负责：

- 管理通用异常检测规则。
- 管理 AgentType 专属异常检测规则。
- 管理 AgentType 黑名单。
- 管理通用和 AgentType 自定义风险判定规则。
- 为检测引擎提供某个 AgentType 的最终生效配置。

### 不直接修改内置规则

当前 `internal/detection/rules.go` 的 `DefaultRules()` 是内置规则词表，建议保留。

新增配置层后，内置规则可以被包装成可配置规则：

| 规则来源 | 说明 | 是否可编辑 |
| --- | --- | --- |
| `builtin` | Go 代码里的内置规则，例如 prompt injection、dangerous command | 可启停、可覆盖 severity/confidence/priority，不物理删除 |
| `custom` | 用户在页面新增的规则 | 可新增、编辑、删除、启停 |
| `blacklist` | AgentType 黑名单自动生成的规则 | 由黑名单项生成，不在普通规则表里直接编辑 |

### 推荐执行流程

```text
BehaviorEvent 写入数据库
        ↓
检测引擎读取事件上下文
        ↓
根据 agent_id 找到 agent_type_id
        ↓
读取 AgentType 生效配置
        ↓
运行通用规则、专属规则、黑名单规则
        ↓
记录 runtime_detections
        ↓
按风险判定策略生成 runtime_decisions
        ↓
按决策生成 response / attack chain
```

### 配置生效规则

后端需要提供一个“有效配置”解析函数，例如：

```go
EffectiveRuntimeDetectionConfig(agentTypeID int64) Config
```

解析逻辑：

1. 读取全局启用的通用规则。
2. 读取 AgentType 设置。
3. 如果 `inherit_global_rules=true`，合并通用规则。
4. 合并该 AgentType 专属规则。
5. 把 AgentType 黑名单转换为检测规则。
6. 如果 `use_global_risk_policy=true`，使用全局风险策略。
7. 否则使用 AgentType 自定义风险策略。

### 缓存与失效

异常检测配置会影响热路径，所以建议缓存：

- 缓存 key：`agent_type_id`
- TTL：5 到 30 秒
- 配置变更后主动失效缓存
- 写入 change domain：`runtime_detection_settings`

### 与回放任务的关系

规则变化不会自动重算历史事件。推荐交互：

1. 用户保存规则。
2. 前端提示：“新规则将影响后续事件；如需应用到历史数据，请执行事件检测重放。”
3. 用户点击重放后调用：

```http
POST /api/v1/jobs
```

请求：

```json
{
  "kind": "event_replay",
  "trigger": "manual",
  "scope": {
    "agent_type_id": 1
  }
}
```

## 数据库设计

### runtime_detection_rules

用于保存通用规则和 AgentType 专属规则。

```sql
CREATE TABLE runtime_detection_rules (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  rule_id TEXT NOT NULL,
  rule_name TEXT NOT NULL,
  source TEXT NOT NULL DEFAULT 'custom',
  scope TEXT NOT NULL DEFAULT 'global',
  agent_type_id INTEGER,
  detection_type TEXT NOT NULL,
  category TEXT NOT NULL DEFAULT 'suspicious',
  severity TEXT NOT NULL DEFAULT 'MEDIUM',
  confidence REAL NOT NULL DEFAULT 0.8,
  matcher_json TEXT NOT NULL DEFAULT '{}',
  detail TEXT NOT NULL DEFAULT '',
  remediation TEXT NOT NULL DEFAULT '',
  priority INTEGER NOT NULL DEFAULT 100,
  enabled INTEGER NOT NULL DEFAULT 1,
  system INTEGER NOT NULL DEFAULT 0,
  version INTEGER NOT NULL DEFAULT 1,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  "delete" INTEGER NOT NULL DEFAULT 0,
  FOREIGN KEY (agent_type_id) REFERENCES agent_types(id) ON DELETE CASCADE
);
```

约束建议：

```sql
CREATE UNIQUE INDEX idx_runtime_detection_rules_unique
ON runtime_detection_rules(scope, COALESCE(agent_type_id, 0), rule_id)
WHERE "delete" = 0;
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| `source` | `builtin` / `custom` |
| `scope` | `global` / `agent_type` |
| `agent_type_id` | AgentType 专属规则时必填 |
| `matcher_json` | 自定义规则匹配条件 |
| `system` | 是否系统内置规则 |
| `delete` | 软删除 |

### runtime_detection_agent_type_settings

用于保存 AgentType 的继承和风险策略开关。

```sql
CREATE TABLE runtime_detection_agent_type_settings (
  agent_type_id INTEGER PRIMARY KEY,
  enabled INTEGER NOT NULL DEFAULT 1,
  inherit_global_rules INTEGER NOT NULL DEFAULT 1,
  use_global_risk_policy INTEGER NOT NULL DEFAULT 1,
  custom_risk_policy_id INTEGER,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  FOREIGN KEY (agent_type_id) REFERENCES agent_types(id) ON DELETE CASCADE
);
```

### runtime_detection_blacklist_items

用于保存 AgentType 黑名单。

```sql
CREATE TABLE runtime_detection_blacklist_items (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  agent_type_id INTEGER NOT NULL,
  target_type TEXT NOT NULL,
  match_type TEXT NOT NULL,
  value TEXT NOT NULL,
  detection_type TEXT NOT NULL DEFAULT 'blacklist_match',
  category TEXT NOT NULL DEFAULT 'attack',
  severity TEXT NOT NULL DEFAULT 'HIGH',
  confidence REAL NOT NULL DEFAULT 0.95,
  reason TEXT NOT NULL DEFAULT '',
  priority INTEGER NOT NULL DEFAULT 50,
  enabled INTEGER NOT NULL DEFAULT 1,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  "delete" INTEGER NOT NULL DEFAULT 0,
  FOREIGN KEY (agent_type_id) REFERENCES agent_types(id) ON DELETE CASCADE
);
```

黑名单类型建议：

| target_type | 示例 |
| --- | --- |
| `command` | `rm -rf`, `powershell -enc` |
| `path` | `/etc/shadow`, `C:\Users\*\AppData\Roaming\*` |
| `tool` | `run_shell`, `read_file` |
| `mcp` | `unknown-mcp-server` |
| `domain` | `pipedream.net` |
| `url` | `http://169.254.169.254/*` |
| `process` | `cmd.exe`, `powershell.exe` |

匹配方式建议：

| match_type | 说明 |
| --- | --- |
| `exact` | 精确匹配 |
| `contains` | 包含 |
| `prefix` | 前缀 |
| `glob` | 通配符 |
| `regex` | 正则，必须限制复杂度 |

### runtime_risk_policies

保存通用风险策略和 AgentType 自定义风险策略。

```sql
CREATE TABLE runtime_risk_policies (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  policy_key TEXT NOT NULL,
  name TEXT NOT NULL,
  scope TEXT NOT NULL DEFAULT 'global',
  agent_type_id INTEGER,
  description TEXT NOT NULL DEFAULT '',
  enabled INTEGER NOT NULL DEFAULT 1,
  system INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  "delete" INTEGER NOT NULL DEFAULT 0,
  FOREIGN KEY (agent_type_id) REFERENCES agent_types(id) ON DELETE CASCADE
);
```

### runtime_risk_policy_rules

保存风险分值区间和决策映射。

```sql
CREATE TABLE runtime_risk_policy_rules (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  policy_id INTEGER NOT NULL,
  risk_level TEXT NOT NULL,
  min_score REAL NOT NULL,
  max_score REAL NOT NULL,
  decision TEXT NOT NULL,
  priority INTEGER NOT NULL DEFAULT 100,
  enabled INTEGER NOT NULL DEFAULT 1,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  FOREIGN KEY (policy_id) REFERENCES runtime_risk_policies(id) ON DELETE CASCADE
);
```

后端 canonical `decision` 建议使用已有枚举：

| 页面展示 | 后端保存 |
| --- | --- |
| ALLOW | `ALLOW` |
| ALERT | `ALERT` |
| ASK | `CONFIRM` |
| BLOCK | `BLOCK` |

## 前端设计落地

### 页面数据流

页面初始化时建议并行请求：

1. 通用异常检测规则列表。
2. 通用风险判定规则。
3. AgentType 专属配置列表。

进入 AgentType 详情弹窗时再请求：

1. AgentType 基础设置。
2. 专属异常检测规则。
3. 黑名单列表。
4. 当前风险判定方式。
5. 如果是自定义风险判定，再读取自定义风险规则。

### 前端类型

建议新增 TypeScript 类型：

- `RuntimeDetectionRule`
- `RuntimeDetectionRuleInput`
- `RuntimeRiskPolicy`
- `RuntimeRiskPolicyRule`
- `RuntimeDetectionAgentTypeSetting`
- `RuntimeDetectionAgentTypeConfig`
- `RuntimeDetectionBlacklistItem`

### Tauri bridge

建议在 `desktop/src-tauri/src/commands` 下增加新 command 文件，例如：

```text
runtime_detection_settings.rs
```

职责：

- 只做参数转换和 HTTP 请求。
- 不在 Tauri 端实现业务规则。
- Go 后端不可用时返回错误，由前端页面显示空态或错误提示。

### 与现有页面关系

异常检测设置页影响：

- 新发生的 runtime detection。
- 手动执行 event replay 后生成的历史 detection。
- 后续 runtime decision 和 attack chain。

它不直接影响：

- 静态资源扫描规则。
- Agent 发现规则。
- 静态资源风险解释规则，除非后续显式做规则联动。

## 实施顺序

1. Go 后端先新增数据表和 store CRUD。
2. Go 后端新增 runtime detection settings API。
3. 检测引擎增加有效配置解析，但先保持 `DefaultRules()` 作为默认通用规则。
4. PolicyEngine 把硬编码 `Decide()` 改为读取 runtime risk policy。
5. Tauri 增加转发命令。
6. 前端增加类型和 bridge。
7. 前端页面接入列表、通用规则、AgentType 详情弹窗。
8. 规则保存后提示用户可以执行 event replay 应用到历史数据。

## 需要注意的边界

- 内置规则不要物理删除；删除可实现为禁用或隐藏。
- AgentType 专属规则默认是增强，不是替换。
- 黑名单本质上也是检测规则，但前端单独管理，便于用户理解。
- 风险判定里的 `ASK` 要映射为现有后端 `CONFIRM`。
- 自定义规则 matcher 需要限制正则复杂度，避免热路径性能问题。
- 规则变更应写入审计日志和 change domain。
