## 页面结构

页面建议沿用 `StaticAssetsPage` 的信息层级和整体布局：左侧为深色导航栏，主工作区使用 `#f3f7fb` 浅色背景，统计卡、Agent 列表、类型卡和表格都使用白色卡片；详情打开时参考现有资源详情样式，页面加灰色遮罩，右侧抽屉使用深蓝背景。主强调色使用 `#1677ff`，风险只在标签、数字和状态上用橙色/红色，避免整页过度警戒化。

1. 顶部标题区：页面名、运行模式、刷新按钮。
2. 顶部统计卡：总异常事件、攻击事件、高危及以上、未解决事件。
3. AgentType 汇总区：展示每类 Agent 的 `total_events` 与动态 `risk_counts`，支持点击后按 Agent 类型筛选。
4. 左侧 Agents 列表：按 Agent 实例选择，使用 `agent_id` 精确筛选列表。
5. 主表格：展示异常检测事件，支持关键字、类别、检测类型、风险、状态、来源、AgentType、Session、Trace、时间范围、排序和分页。
6. 右侧抽屉：点击某一行后展示 Detection 基础信息、Evidence、上下文和处置入口。

## 接口使用

### 1. 顶部/AgentType 汇总

使用新接口：

```http
GET /api/v1/runtime-detections/summary/agent-types
```

用途：

- 给页面上方的 AgentType 汇总卡片或柱状统计提供数据。
- 返回 `agent_type_id`、`agent_type`、`total_events`。
- `risk_counts` 根据数据库实际 `severity` 动态生成，不应在前端写死枚举。
- 缺失风险等级会进入 `unknown`。
- 支持复用列表接口的筛选条件，例如 `category`、`keyword`、`severity`、`status`、`source`、`agent_id`、`AgenttypeId`、`session_id`、`trace_id`、`start_time`、`end_time`。
- 额外支持 `agent_type` 精确筛选，可按类型 key、名称或 ID 匹配。

前端使用建议：

- 初始进入页面时请求一次全局 AgentType 汇总。
- 当用户切换风险、状态、类别、来源、关键字、时间范围时，同步带上相同筛选参数重新请求汇总。
- 当用户点击某个 AgentType 卡片时，将该类型的 `agent_type_id` 作为列表查询的 `AgenttypeId`。
- `page`、`page_size`、`limit`、`offset` 对该汇总接口无意义，可不传。

### 2. 左侧 Agents 列表

继续使用现有 Agent 列表能力：

```http
GET /api/v1/agents?page_size=1000
```

用途：

- 给左侧 Agents 列表提供 Agent 实例。
- 点击 Agent 后，列表接口传 `agent_id`。
- `agent_id` 是实例 ID；`AgenttypeId` 是 Agent 类型 ID，两者可以同时传，语义是 AND。

### 3. 异常事件列表

使用列表接口：

```http
GET /api/v1/runtime-detections
```

用途：

- 给主表格提供分页数据。
- 表格分页读取 `list`，并兼容 `items` / `detections`。
- `total` 用于分页总数。
- `summary` 中 `attack/blocked/critical/high/open` 只适合做当前页辅助统计，不应替代新的 AgentType 汇总接口。

主要参数：

- `page`、`page_size`：服务端分页，事件页建议默认 `page=1&page_size=20`。
- `keyword`：模糊搜索 Detection、Agent、Session、Trace、类型、规则等。
- `sort`：默认按 `last_seen_at` 倒序。
- `agent_id`：左侧 Agent 实例筛选。
- `AgenttypeId`：Agent 类型筛选。
- `category`：攻击事件用 `attack`，可多值。
- `detection_type`：检测类型，可多值。
- `severity`：风险等级，可多值，如 `critical,high`。
- `status`：状态，可多值，如 `open,mitigated,resolved`。
- `source`：检测来源，可多值。
- `session_id` / `trace_id`：上下文精确查询。
- `start_time` / `end_time`：时间窗口。

### 4. 异常事件详情

点击表格行后请求：

```http
GET /api/v1/runtime-detections/{detection_id}
```

用途：

- 填充右侧抽屉。
- `detection` 展示基础字段。
- `evidence` 展示支撑该 Detection 的原始行为事件。
- `agent` 展示 Agent 上下文。
- `runtime_session` / `trace` 展示会话与调用链信息。

如需单独刷新证据，可使用：

```http
GET /api/v1/runtime-detections/{detection_id}/events
```

### 5. 可选处置接口

如果详情抽屉保留“预览/执行阻断”能力，可继续使用：

```http
POST /api/v1/runtime-detections/{detection_id}/actions/block
```

建议交互：

- 先 preview，展示 enforcement point、action type、target。
- 用户确认后再执行真实阻断。
- 执行成功后刷新汇总、列表和当前详情。

## 推荐请求流程

1. 页面初始化：并行请求 Agent 列表、全局安全汇总、AgentType 汇总、事件列表。
2. 用户选择左侧 Agent：更新 `agent_id`，重新请求 AgentType 汇总和事件列表。
3. 用户点击 AgentType 汇总卡：更新 `AgenttypeId`，重新请求 AgentType 汇总和事件列表。
4. 用户修改表格筛选条件：重置 `page=1`，重新请求 AgentType 汇总和事件列表。
5. 用户翻页：只重新请求事件列表，不必请求汇总。
6. 用户点击事件行：请求详情接口，打开右侧抽屉。
