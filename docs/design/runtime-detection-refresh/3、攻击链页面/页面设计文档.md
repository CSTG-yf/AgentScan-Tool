## 页面设计

整体样式对齐静态资源页：左侧深色导航，顶部白色工作台栏，主体为浅灰蓝背景和白色内容卡片。攻击链页面不做营销式说明，首屏直接呈现安全运营需要的工作台。

页面上方放 4 个统计卡片：覆盖 Agent、攻击链总数、活跃攻击链、高危及以上。这里的统计可以由攻击链列表和 AgentType 汇总接口共同计算；如果后续有独立总览接口，可以替换成独立总览数据源。

左侧保留 Agents 列表，用于按 Agent 实例筛选攻击链。每个 Agent 项展示链路数和重点风险数量，选中后右侧表格、页头摘要与 AgentType 汇总同步刷新。

主体区域不再额外放一组 Agent 卡片，避免和左侧 Agents 列表重复。右侧只保留当前筛选摘要和攻击链表格；Agent 选择统一放在左侧，AgentType 汇总数据用于支撑顶部统计、左侧数量提示和筛选后的分布摘要。

表格是页面主操作区，支持 keyword、攻击类型、风险等级、状态、时间排序等筛选。点击行后右侧打开深蓝详情抽屉，背景置灰，抽屉展示链路身份、摘要、步骤时间线、证据、检测、决策和响应动作。

## 接口使用

1. 汇总接口：`GET /api/v1/attack-chains/summary/agent-types`

用于页面汇总统计和筛选分布。返回 `agent_type_id`、`agent_type`、`total_chains`，并额外返回动态 `status_counts`、`severity_counts`。前端展示时不要写死状态和风险枚举，应按后端返回的 map 动态渲染；缺失或未知类型可归到 `unknown`。当前设计不再把 AgentType 渲染成主区域横向列表，避免和左侧 Agents 列表重复。

2. 列表接口：`GET /api/v1/attack-chains`

用于攻击链表格。主要查询参数包括 `page`、`page_size`、`agent_id`、`session_id`、`trace_id`、`AgenttypeId`、`attack_type`、`severity`、`status`、`start_time`、`end_time`、`keyword`、`sort`。风险等级查询前转大写；`blocked`、`mitigated` 可映射为后端原始 `contained`。分页只刷新列表，筛选条件变化时应同时刷新列表和汇总。

3. 详情接口：`GET /api/v1/attack-chains/{attack_chain_id}`

用于右侧详情抽屉。身份和原始状态优先读取 `attack_chain`；页面展示对象读取 `chain`；步骤图和时间线读取 `nodes` 或 `chain.steps`；证据读取 `evidence`；检测、决策和响应读取 `detections`、`decision`、`responses`、`response`。是否真正阻断需要结合 `responses.status` 与原始行为 `outcome`，不要只依赖风险等级或 `would_block`。

## 推荐加载流程

页面初始化时并行请求 Agents、攻击链列表和 AgentType 汇总。用户选择 Agent、AgentType 或修改筛选条件时，带同一组筛选条件刷新列表和汇总；用户翻页时只刷新列表；用户点击攻击链行时再请求详情接口打开抽屉。

当前桌面端已经接入 `getAttackChainAgentTypeSummaries` 的无参汇总封装；如果要让汇总统计完全跟随表格筛选，需要把列表页的筛选参数继续透传到 Tauri command 和 Go 后端汇总接口。
